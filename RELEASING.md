# Releasing rockets-engine

Step-by-step for cutting a release and shipping the site + downstream pin.
Every step is the exact command this repo has been shipped with. Do not
deviate without updating this file.
Account-specific values (the AWS bucket, distribution and other
infrastructure identifiers, and the downstream repository) live in the local,
git-ignored AGENTS.md, not in this public file.

## Authorship

- Commit with the developer's own Git identity for both author and committer
  (configured in this repository's local Git config).
- Never add AI/assistant/model attribution to commits, PRs, files or docs.
  No co-author trailers, no "generated by" notices.

## 1. Version bump — all five places, every time

1. `Cargo.toml`: `version = "0.N.0"`.
2. `site/index.html`: the `<h1>` badge `v0.N.0`.
3. `site/index.html`: the install snippet `rockets-engine = "0.N"` (the
   `# Cargo.toml` block).
4. `site/index.html`: the code-note reference `rockets-engine = "0.N"`
   (next to the `ballistics-engine` pin).
5. `README.md`: `rockets-engine = "0.N"`.

CI's "Version strings match Cargo.toml" step fails if any snippet drifts,
so a grep for the old version after bumping tells you what you missed:

```sh
grep -rn 'rockets-engine = "0\.' site/index.html README.md
```

## 2. Rebuild and verify

```sh
cargo generate-lockfile
./scripts/build-wasm.sh          # regenerates site/sh/wasm/*
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-features
for f in cli ballistics model serde; do
  cargo test --no-default-features --features $f
done
cargo check --no-default-features --features wasm,ballistics --target wasm32-unknown-unknown
```

All must be green before committing. `cargo package --list` should show no
`site/` files and no `RELEASING.md` (both are excluded in Cargo.toml).

## 3. Commit, publish, push

```sh
git add -A
git commit -m "…"
cargo publish --locked --all-features
git push origin main
```

## 4. Deploy the site

With `SITE_BUCKET` and `DISTRIBUTION_ID` set from AGENTS.md:

```sh
aws s3 sync site/ "s3://$SITE_BUCKET/" --delete
INV=$(aws cloudfront create-invalidation --distribution-id "$DISTRIBUTION_ID" --paths "/*" --query 'Invalidation.Id' --output text)
aws cloudfront wait invalidation-completed --distribution-id "$DISTRIBUTION_ID" --id "$INV"
curl -s https://rockets.rs/ | grep -o 'v0\.N\.0'   # confirm the badge
```

The site is a private S3 bucket behind CloudFront with a URL-rewrite
function that appends index.html for `/sh/`. Do not change the
infrastructure casually; its identifiers are in AGENTS.md.

## 5. Bump the downstream pin

The game workspace pins rockets-engine exactly. Change its pin to `=0.N.0`,
run its tests, and commit "Take rockets-engine 0.N.0". The repository path
and the exact steps are in AGENTS.md.

## 6. Green CI

```sh
gh run list --repo ajokela/rockets-engine --limit 1 --json databaseId --jq '.[0].databaseId' \
  | xargs -I{} gh run watch {} --repo ajokela/rockets-engine --exit-status
```

## Physics-parity notes (if you touch the geometry modeler)

Any change to drag/Cnα/CP must be re-validated against OpenRocket:

- `scripts/openrocket-parity/README.md` documents reproducing the fixed
  OpenRocket 24.12 jar (`release-24.12`) flights (A8/D21/G64/Beta) and the
  like-for-like configuration (rounded fins, SMOOTH finish, no launch lug).
- The `openrocket-parity` CI job downloads the jar, runs the driver, and
  injects the live apogees (`ROCKETS_OPENROCKET_*_APOGEE_M`). Re-run
  `scripts/openrocket-parity/Apogee.java` and re-pin the constants in
  `src/command.rs` when the physics changes; each flight must stay within
  10% of OpenRocket.

## Dependency pins (verify before publishing)

- `winds-engine = "=0.N.0"` with `features = ["grib"]` — keep exact.
