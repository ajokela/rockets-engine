rockets-engine v0.20.0

Point-mass powered flight for Rust — prescribed motor burns, staging and guidance hooks on the ballistics-engine force kernel.

# Cargo.toml
rockets-engine = "0.20"

What it does

  • Prescribed thrust curves — piecewise-linear burns with analytic propellant mass; no separate fuel integrator to drift.
  • Serial & parallel staging — any number of stages, each with its own motor schedule and separation time; mass stays analytic across separations.
  • Discontinuity-aware RK4 — ignition, curve knots, separations and burnout split the integration grid; one-sided forces at every event.
  • Guidance hooks — application-owned controllers called once per public step; the integrator holds the command constant across substeps.
  • Real force models — ballistics-engine gravity, drag and ICAO atmosphere; central (inverse-square) gravity for planet-scale ECI arcs, and altitude switching to a vacuum model above the atmosphere in flat or launch-local frames, where Y is altitude.
  • Modified point-mass — opt-in Magnus/yaw-of-repose spin, Coriolis and rail tip-off, plus angle-of-attack body lift and induced drag. No attitude integration required.
  • CLI & browser terminal — cargo install rockets-engine --features cli for the rockets tool, or fly it in the browser terminal; one shared parser, native and WASM. Monte-Carlo dispersion and elevation solving built in.
  • Guidance composition — prograde gravity turns, thrust-misalignment dispersion, actuator lag and launch rails, with downrange-segmented atmosphere and wind.
  • Reduced-order dynamics — second-order weathercock with CP/CG curves and a scalar roll channel: body-axis response and spin history without a 6-DOF attitude model.
  • Model-rocket pack — RASP .eng motor files, apogee parachute recovery with natural terminal velocity, and illustrative 24/54 mm airframe presets.
  • Geometry modeler — subsonic Barrowman aerodynamics: describe the nose, tube and fins, get Cd/Cnα/CP curves and a flight. Validated against OpenRocket's formulas.
  • SI throughout — metres, seconds, kilograms, newtons. Simulation time in, state out; the solver owns no evolving state.

Use them together

The boundary: rockets-engine owns the powered flight — motor, mass, integration, guidance. ballistics-engine supplies the atmosphere and drag kernel through the adapter.

use rockets_engine::{
    ballistics::{Atmosphere, BallisticForces},
    ControlInput, FlightState, IntegratorSettings, Motor, Rocket, Simulator,
    ThrustCurve, ThrustPoint, Vec3,
};

fn main() -> Result<(), rockets_engine::Error> {
    // rockets-engine: prescribed motor burn
    let curve = ThrustCurve::new(vec![
        ThrustPoint { time_s: 0.0, thrust_n: 0.0 },
        ThrustPoint { time_s: 0.1, thrust_n: 20.0 },
        ThrustPoint { time_s: 0.9, thrust_n: 15.0 },
        ThrustPoint { time_s: 1.0, thrust_n: 0.0 },
    ])?;
    let rocket = Rocket::new(0.18, Some(Motor::new(curve, 0.04, 0.2)?))?;

    // ballistics-engine: atmosphere + drag kernel (via the adapter)
    let forces = BallisticForces::new(
        0.025,
        vec![(0.0, 0.45), (0.8, 0.5), (1.2, 0.7), (3.0, 0.4)],
        Atmosphere::default(),
        Vec3::new(2.0, 0.0, 0.0),
    )?;

    let sim = Simulator::new(rocket, forces, IntegratorSettings::default())?;
    let mut state = FlightState {
        time_s: 0.0,
        position_m: Vec3::new(0.0, 2.0, 0.0),
        velocity_mps: Vec3::new(2.0, 8.0, 0.0),
    };
    for _ in 0..100 {
        let result = sim.step(&state, 0.05, ControlInput::along(Vec3::new(0.3, 1.0, 0.0)))?;
        state = result.state;
    }
    Ok(())
}

In Cargo.toml: rockets-engine = "0.20"; add ballistics-engine = "=0.49.0" only if you call its API directly. Full source: examples/with_ballistics.rs. Flying something unpowered? Drive ballistics-engine directly instead.

Model a rocket from geometry

Describe the airframe instead of guessing curves. The Barrowman modeler turns nose, tube and fin geometry into Cd/Cnα/CP, the weathercock uses CP/CG for stability, and the recovery model brings it home. One command exercises the whole stack:

simulate \
  --motor estes:d12 \
  --geometry nose=conical:0.1:0.024,tube=0.4:0.024,fins=3:0.05:0.03:0.04:0.02:0.002 \
  --geometry-masses 0.012,0.020,0.006 \
  --weathercock --recover 0.25 --plot

--motor picks a built-in NAR-data curve (estes:a8, b6, c6, d12 and aerotech:g80 today); --motor-eng takes any RASP .eng text pasted inline (\n escapes mark its line breaks for single-line terminals), and --motor-file reads one from disk. --geometry is nose=shape:length:diameter,tube=length:diameter,fins=count:root:tip:span:sweep:thickness, in metres. --geometry-masses is the nose, tube and fin mass in kg — from those the engine works out the dry mass (adding the motor casing), the dry CG, the propellant CG and the pitch inertia, so there is nothing left to guess. --weathercock turns on second-order stability dynamics; --recover is the parachute's Cd·A in m². The real D12 has 16.9 N·s of total impulse and reaches about 550 m on the 58 g airframe. Launch elevation defaults to 90° (straight up); add --elevation-deg for angled flights.
